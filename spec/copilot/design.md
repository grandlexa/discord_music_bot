# Дизайн и архитектура проекта 🎯

## Краткое описание
Это Discord-бот для воспроизведения музыки во голосовых каналах Discord. Основной функционал: поиск треков (YouTube/ссылка/плейлист), поддержка очереди, управление воспроизведением (play/pause/next/prev/stop/seek), регулировка громкости, UI-виджет (embed + кнопки) и автоматическое отключение при неактивности.

## Точки входа
- `app/__main__.py` — точка входа при запуске `python -m app` (использует `app.core.bot.run_bot`).
- `app/main.py` — альтернативная (монолитная) реализация бота и также запускается как `python main.py` (используется в Dockerfile: `CMD ["python", "main.py"]`).

> Замечание: в репозитории присутствуют две реализационные ветки (монолит `app/main.py` и модульный `app/core/*`). При создании копии проекта рекомендуется выбрать **модульный** вариант (`app/core`, `app/commands`, `app/services`, `app/ui`) как основу.

## Компоненты и их ответственность 🔧

1. core
   - `app/core/config.py` — конфигурации (логирование, `YDL_OPTIONS`, `FFMPEG_OPTIONS`, `BOT_TOKEN`, `BOT_PREFIX`, `BOT_INTENTS`).
   - `app/core/bot.py` — инициализация `discord.ext.commands.Bot`, регистрация команд, запуск бота и глобальный обработчик ошибок.

2. commands
   - `app/commands/music_commands.py` — реализация команд (`play`, `pause`, `resume`, `stop`, `next/skip`, `prev`, `np`, `queue`, `shuffle`, `volume`, `info`), реализация логики начала воспроизведения через `play_next`.

3. services
   - `app/services/youtube_service.py` — поиск и разрешение треков через `yt_dlp` (`search_and_extract_tracks`, `resolve_track_stream_url`, `create_track_info`).
   - `app/services/queue_service.py` — управление очередью (создание / очищение / состояние / задачи таймеров и fade-тасков).
   - `app/services/media_service.py` — вспомогательные функции аудио: `parse_time`, `volume_fade`, `fade_out_task_func`, `get_current_volume`.

4. ui
   - `app/ui/player_ui.py` — формирование embed-ов и `View` (кнопки и модальные окна) для управления воспроизведением и отображения очереди.

5. Инфраструктура
   - `Dockerfile` — образ на базе `python:3.12-slim`, устанавливает `ffmpeg` и Python зависимости, копирует `app/` в контейнер и запускает `main.py`.
   - `docker-compose.yml` — простой сервис `discord-bot` с пробросом переменной окружения `DISCORD_BOT_TOKEN`.

## Модель данных (ключевые структуры) 📦
- Трек (dict):
  - `url` — исходный URL или ссылка на YouTube
  - `title` — название
  - `duration` — длительность в секундах
  - `requester` — упоминание пользователя, добавившего трек
  - (опционально) `stream_url` — разрешённая прямая ссылка потока
  - (опционально) `thumbnail` — URL миниатюры

- Очередь (в `queue_service.queues`):
  - `queue` — list[track]
  - `current_index` — индекс текущего трека (-1 если пусто)
  - `is_seeking`, `seek_time` — параметры перемотки
  - `current_message` — сообщение с плеером (embed)
  - `disconnect_task`, `fade_in_task`, `fade_out_task` — asyncio.Tasks
  - `start_time` — время старта текущего трека

## Асинхронная модель и задачи
- Асинхронность строится на `asyncio`, используется петля бота (`bot.loop` / `ctx.bot.loop`) для постановки задач (`create_task`) и `run_in_executor` для выполнения блокирующих вызовов `yt_dlp`.
- Взаимодействие с голосовым клиентом зависит от `discord` API (`voice_client.play`, `pause`, `resume`, `stop`, `disconnect`).

## Поведения и особенности
- Fade-in/ Fade-out для плавного переключения громкости у треков.
- Поддержка перемотки: modal ввод времени, установка `is_seeking` и `seek_time` и перезапуск плеера.
- Защита от tight loop при ошибках загрузки трека (increment index, sleep(1)).
- Автоматический таймер отключения при бездействии (по умолчанию 120 секунд).

## Важные замечания / Точки риска ⚠️
- В репозитории содержится две реализации логики (монолитная и модульная) — нужно выбрать одну и удалить дубликаты при копировании.
- Непоследовательность реализации `volume_fade` (в `main.py` — 20 шагов/сек, в `media_service.py` — 2 шага/сек) — нужно унифицировать.
- Зависимость от `yt_dlp` требует запуска сетевых вызовов в executor; модуль `youtube_service.py` делает это в `resolve_track_stream_url`, но `search_and_extract_tracks` выполняет синхронный вызов (в `commands.play` он запускается синхронно и возвращает список) — для масштабируемости и тестируемости стоит делать сетевые вызовы в executor.
- Отсутствие модульных тестов — лучше покрыть логику поиска/разрешения треков, очереди и UI создания. 

## Развертывание
- Требуется переменная окружения: `DISCORD_BOT_TOKEN`.
- Контейнер требует системного пакета `ffmpeg` (установлен в Dockerfile).
