# Wrap-up — Результаты анализа и рекомендации ✅

## Краткое резюме
- Проект — Discord music bot с двумя видимыми реализациями: монолитной (`app/main.py`) и модульной (`app/core`, `app/commands`, `app/services`, `app/ui`).
- Я подготовил полный набор документов для восстановления проекта ИИ-агентом: `design.md`, `requirements.md`, `functional_spec.md`, `tasks.md`, `tests.md`, `agent_tasks.md`.

## Основные находки
- Различия в реализации (монолит vs модульный): нужно выбрать один подход и удалить дублирующие файлы.
- Несогласованность в `volume_fade` (разные шаги/частоты в разных модулях) — требуется унификация.
- Некоторые сетевые операции выполняются синхронно (в `search_and_extract_tracks`), рекомендуется исполнять их в `executor` для предсказуемости и тестируемости.

## Рекомендации по приоритетам
1. Выбрать архитектурную ветку: модульный подход (`app/core` + `app/commands/...`) — легче для тестирования и расширения.
2. Устранить несогласованности (volume_fade, тайминги) и добавить конфигурацию для параметров fade.
3. Добавить полный набор unit/integration тестов и CI (GitHub Actions).
4. Подготовить `Dockerfile` и `docker-compose` для production и CI сборки.
