# Функциональная спецификация — команды и поведение ⚙️

## Цель
Точная и недвусмысленная спецификация поведения каждой команды и взаимодействия системы, чтобы ИИ-агент мог воспроизвести функциональность без двусмысленностей.

---

## Общие принципы
- Ответы бота должны быть понятными и короткими (эмодзи + текст), как в текущей реализации (например, "👍 Добавлено в очередь: **title**").
- Все сетевые вызовы (yt-dlp) выполняются в `executor` (не блокировать event loop).
- Все изменения состояния очереди — атомарные (через `queue_service` API), чтобы облегчить тестирование и избежать race conditions.
- Ошибки и исключения логируются, пользователю отправляется дружественное сообщение.

---

## Команды (детально)

1) `!play <query>`
- Вход: строка `query` (URL/название/плейлист)
- Поведение:
  - Проверить, что пользователь находится в голосовом канале. Если нет → `"Вы должны быть в голосовом канале."`.
  - Подключиться к голосовому каналу, если бот ещё не подключён или в другом канале — `connect`/`move_to`.
  - Поиск треков через `youtube_service.search_and_extract_tracks(query, ctx.author.mention)` (в executor если требуется).
  - Если нет результатов/ошибка → `"❌ Не удалось найти видео..."`.
  - Добавить найденные треки в очередь через `queue_service.add_track`.
  - Если бот не играет — вызвать `play_next(ctx)`.
- Выход: одно или несколько сообщений в чат (статус поиска, добавление в очередь или ошибка).

Edge-cases:
- Плейлист: добавить все треки (сообщение "Добавлено N треков").
- Ограниченный/недоступный контент: пропустить с логом и сообщением пользователю.

2) `!pause` / `!resume`
- `pause`: если `voice_client.is_playing()` → `pause()`, сообщение: `"⏸️ Музыка на паузе."` иначе `"Сейчас ничего не играет."`.
- `resume`: аналогично с `resume()`.

3) `!stop`
- Очищает очередь (`clear_queue`), останавливает текущий трек и отключается из voice channel.
- Ответ: `"⏹️ Музыка остановлена, очередь очищена."`.

4) `!next` / `!skip`
- Если играет/на паузе — `voice_client.stop()` (триггерит `after` и `play_next`). Ответ: `"⏭️ Включаю следующий трек..."`.
- Если нет трека — `"Очередь пуста или музыка не играет."`.

5) `!prev`
- Проверить `current_index` > 0. Уменьшить `current_index` на 2 (play_next увеличит на 1) и `voice_client.stop()`.
- Ответы: ошибки (первый трек) — `"⏮️ Это первый трек..."`.

6) `!queue` / `!list`
- Создаёт embed с up to 40 элементами, начиная с текущего индекса.
- Формат строки: `▶️ **{title}** | `HH:MM:SS`` для текущего и `` `{i}.` `` для остальных.

7) `!np` / `!nowplaying`
- Показать embed с прогресс-баром (20 символов), длительностью и тем, кто заказал.
- Если live или duration==0 → `Live / ???`.

8) `!shuffle`
- Перемешивает только будущие треки (индекс +1 ... end).
- Если недостаточно треков → сообщение: `"Недостаточно треков для перемешивания."`.

9) `!volume <0-100>`
- Установить `voice_client.source.volume = volume/100.0`. Валидация: `0 <= volume <= 100`.

10) UI Buttons (в `player_ui`)
- Prev, Pause/Resume, Stop, Next, Seek (modal), Info, List, Shuffle — должны повторять поведение команд и работать через `server_queue` API.

## Поведение `play_next` (ключевая функция)
1. Проверить `voice_client`/`is_connected`.
2. Отменить предыдущие fade задачи (если есть).
3. Увеличить `current_index` (если не `is_seeking`).
4. Цикл: для `current_index < len(queue)`:
   - Получить `track_info`; если нет `stream_url` или `seek_time`>0 — вызвать `resolve_track_stream_url(track_info)` асинхронно.
   - Если resolve потерпел неудачу — log + `current_index += 1` + continue.
   - Подготовить `FFMPEG_OPTIONS` (+ `-ss` если seek).
   - Создать `FFmpegPCMAudio` и обернуть в `PCMVolumeTransformer`.
   - Устанавливать `volume=0.0` и запускать `volume_fade` (duration 3s -> 1.0) как таск.
   - Создать `fade_out_task` для окончания трека (если duration > 2).
   - Отправить/обновить сообщение плеера (`send_player_message`).
   - Выход из функции (успешное воспроизведение).
5. Если очередь закончилась — сообщение о завершении и запуск `disconnect_timer`.

Edge-cases:
- Плохой `stream_url` — лог + пропустить трек
- `seek_time` > track.duration — корректная обработка (например, пропуск или воспроизведение с конца)

## Сценарии ошибок и ответы бота
- `CommandNotFound` → `"❌ Команда не найдена. Используйте !info"`.
- Сетевые ошибки (yt-dlp) → `"❌ Не удалось найти видео. Ошибка: ..."` с логированием стека.
- Ошибки воспроизведения (ffmpeg) → `"❌ Ошибка запуска плеера: ..."`.
