# Пошаговые задачи для ИИ-агента — восстановление проекта с нуля 🧭

Ниже приводится разбивка работы на атомарные задачи, которые ИИ-агент должен выполнить для создания копии проекта с нуля. Для каждого шага указаны критерии приёмки.

---

## 1. Инициализация проекта
- Создать структуру пакетов:
  - `app/core/` (config, bot)
  - `app/commands/` (music_commands)
  - `app/services/` (youtube_service, queue_service, media_service)
  - `app/ui/` (player UI)
  - `tests/` (unit/integration tests)
- Инициализировать `pyproject.toml` или `requirements.txt`.
- Инициализировать git репозиторий (README, .gitignore).

Критерии: проект собирается локально (`pip install -r requirements.txt`), базовый `python -m app` или `python main.py` запускается и логирует старт.

---

## 2. Реализация конфигурации
- Реализовать `app/core/config.py` со всеми настройками и переменными окружения.
- Добавить удобные точки переопределения через env (например: `YDL_OPTIONS` частично через JSON/ENV).

Критерии: доступна переменная `BOT_TOKEN` из env; логирование корректно инициализируется.

---

## 3. Реализация сервисов
- `youtube_service`:
  - `search_and_extract_tracks(query, requester)` — с выполнением сетевого запроса в executor.
  - `resolve_track_stream_url(track)` — асинхронно получает `stream_url`.
  - Моки для тестирования сетевых вызовов.
- `queue_service`:
  - Полный набор операций над очередью + таймеры и управление задачами.
- `media_service`:
  - `parse_time`, `volume_fade` (с параметризированной частотой шагов), `fade_out_task_func`, `get_current_volume`.

Критерии: покрытие unit-тестами всех public функций, тесты имитируют `yt_dlp` и `voice_client`.

---

## 4. UI и команды
- `player_ui` — реализация embed-ов и `discord.ui.View` кнопок.
- `music_commands` — команды с делегированием в сервисы.
- Обработчик ошибок (`on_command_error`) должен корректно реагировать на типы ошибок.

Критерии: логика команд реализована, реакции и embed-ы корректны (можно тестировать с Unit + Mocks).

---

## 5. Поведение воспроизведения
- Реализовать `play_next` с корректной работой `seek`, `fade-in/out`, обработкой ошибок загрузки трека и переключением индекса.
- Убедиться, что все блокирующие операции выполняются в executor.

Критерии: ручное тестирование в тестовом сервере Discord показывает плавные переходы, корректные реакции при ошибках и отключение при бездействии.

---

## 6. Тесты и CI
- Добавить `pytest` + `pytest-asyncio` тесты для:
  - `youtube_service` (mock yt_dlp)
  - `queue_service` (логика очереди + таймеры)
  - `media_service` (volume_fade edge-cases)
  - UI-embed creators
  - E2E-интеграционный тест (опционально) с мнимыми `voice_client`
- Добавить GitHub Actions workflow: `lint`, `test`, `build image`.

Критерии: все тесты проходят в CI, линтер не возвращает критических ошибок.

---

## 7. Docker и деплой
- Восстановить `Dockerfile` (как в репозитории): базовый образ Python 3.12, установить `ffmpeg`, копировать `app/` и `requirements.txt`, CMD — `python main.py`.
- Подготовить `docker-compose.yml` с env переменными и healthchecks.

Критерии: `docker compose up --build` запускает контейнер и бот логируется как "готов к работе".

---

## 8. Финализация: документация и улучшения
- Создать README с примерами использования и настройкой токена.
- Предложить улучшения: конфигурация через файл/ENV, персистентная очередь (опция), лимиты на плейлист, rate-limiting для yt-dlp.

Критерии: README исчерпывающий; PR с предложением улучшений готов.

---

> Каждую задачу следует разбить на маленькие коммиты и валидацию через unit tests. Для каждого шага укажите примерные тесты и критерии приёмки; при необходимости могу сгенерировать конкретные тестовые файлы и шаблоны задач (issues/PR).
