# План реализации Discord Music Bot

## 1. Анализ текущего состояния системы
- **Текущая директория**: Проект находится в начальной стадии развертывания.
- **Наличие файлов**:
    - Полный комплект спецификаций (`spec/copilot/`, `spec/gemini/`), описывающий требования, дизайн и функциональность.
    - Файлы конфигурации окружения (`.env`, `cookies.txt`).
- **Отсутствующие компоненты**:
    - Отсутствует исходный код приложения (`app/` или `src/`).
    - Нет конфигурации для сборки (Dockerfile, docker-compose.yml).
    - Отсутствуют тесты и зависимости.
- **Вывод**: Требуется полная реализация проекта "с нуля", опираясь на предоставленные спецификации и рекомендуемую модульную архитектуру.

## 2. Определение целей и задач проекта
- **Главная цель**: Разработать стабильный, масштабируемый и удобный в использовании музыкальный бот для Discord.
- **Ключевые задачи**:
    1.  **Воспроизведение**: Обеспечить качественное проигрывание аудио с YouTube (видео, стримы, плейлисты) с использованием `yt-dlp` и `ffmpeg`.
    2.  **Очередь**: Реализовать надежную систему управления очередью (FIFO) с возможностью модификации (shuffle, skip, remove).
    3.  **Интерфейс**: Создать современный UX с использованием Discord Buttons и Embeds для управления плеером без ввода команд.
    4.  **Стабильность**: Обеспечить отказоустойчивость (авто-переподключение, обработка ошибок сети и API).
    5.  **Деплой**: Подготовить Docker-окружение для быстрого развертывания.

## 3. Технические требования и ограничения
- **Стек технологий**:
    - **Язык**: Python 3.14.2
    - **Фреймворк**: `discord.py` (v2.5.2+)
    - **Загрузчик**: `yt-dlp` (2025.x+)
    - **Аудио процессинг**: `FFmpeg` (через `discord.FFmpegPCMAudio`)
    - **Голос**: `PyNaCl`
- **Окружение**:
    - Docker (базовый образ `python:3.14.2-slim`)
    - Переменные окружения для конфиденциальных данных.
- **Ограничения**:
    - Обязательное использование `cookies.txt` для доступа к YouTube (предотвращение 429/Sign-in ошибок).
    - Асинхронная архитектура: блокирующие операции (сетевые запросы, процессинг) должны быть вынесены в `executor`.
    - Локализация: Русский язык.

## 4. Архитектурное решение
Проект будет следовать **модульной архитектуре** (в отличие от монолитной), что обеспечит расширяемость и простоту поддержки.

### Структура проекта (`app/`):
- **`core/`**: Ядро приложения.
    - `config.py`: Загрузка и валидация конфигурации.
    - `bot.py`: Инициализация класса бота, setup hook.
    - `logger.py`: Настройка логирования.
- **`services/`**: Бизнес-логика (независимая от discord-контекста где возможно).
    - `queue_service.py`: Управление очередью треков, логика проигрывания.
    - `youtube_service.py`: Обертка над `yt-dlp`, поиск, извлечение метаданных.
    - `media_service.py`: Управление параметрами FFmpeg, эффекты (fade-in/out).
- **`commands/`**: Слой представления (Cogs).
    - `music.py`: Обработка команд (`!play`, `!skip` и т.д.) и взаимодействие с сервисами.
- **`ui/`**: Визуальные компоненты.
    - `player_view.py`: Классы кнопок и View для плеера.
    - `embeds.py`: Фабрики для создания красивых Embed-сообщений.
- **`main.py`**: Точка входа для запуска.

## 5. Этапы реализации с оценкой времени

### Этап 1: Подготовка фундамента
- Инициализация Git.
- Создание структуры директорий.
- Настройка `requirements.txt` и `Dockerfile`.
- Реализация `app/core/config.py` и базового запуска бота.

### Этап 2: Реализация Сервисов (Core Logic)
- **YouTubeService**: Реализация поиска и экстракции ссылок (с поддержкой `cookies.txt`).
- **QueueService**: Структуры данных для хранения треков и состояния плеера.
- **MediaService**: Настройка FFmpeg опций.

### Этап 3: Команды и Воспроизведение
- Интеграция `discord.VoiceClient`.
- Реализация команды `!play` и цикла воспроизведения `play_next`.
- Реализация базового управления: `pause`, `resume`, `stop`, `skip`.
- Обработка событий завершения трека.

### Этап 4: Пользовательский Интерфейс (UI)
- Создание класса `PlayerView` с кнопками.
- Реализация логики обновления сообщения плеера (now playing).
- Добавление модальных окон (например, для Seek).

### Этап 5: Расширенный функционал и Полировка
- Команды `!queue`, `!shuffle`, `!volume`.
- Реализация Fade-in / Fade-out эффектов.
- Обработка ошибок (try-except блоки, user-friendly сообщения).
- Авто-отключение при бездействии.

### Этап 6: Деплой и Финализация (2 часа)
- Настройка `docker-compose.yml`.
- Финальное тестирование в Docker-контейнере.
- Документация (README.md).


## 6. Необходимые ресурсы
- **Человеческие**: 1 AI-Assisted Developer.
- **Технические**:
    - Локальная среда разработки с Python 3.14.2 и FFmpeg.
    - Доступ к Discord Developer Portal (для создания приложения и получения токена).
    - Файл `cookies.txt` (экспорт из браузера).

## 7. Критерии успеха и метрики оценки
1.  **Функциональность**: Бот проходит все сценарии из `functional_spec.md`.
2.  **Надежность**: Бот не падает (crash) при ошибке воспроизведения одного трека, а переходит к следующему.
3.  **Отзывчивость**: Время реакции на команду `!play` до начала воспроизведения (или сообщения о поиске) < 2 сек.
4.  **Качество кода**: Код соответствует PEP8, разбит на модули, имеет тайп-хинты.

## 8. Потенциальные риски и пути их минимизации

| Риск | Вероятность | Влияние | Стратегия минимизации |
|:--- |:---:|:---:|:---|
| **Поломка YouTube API / yt-dlp** | Высокая | Критическое | Регулярное обновление `yt-dlp` в Dockerfile, использование `cookies.txt`, обработка ошибок загрузки. |
| **Блокировка IP со стороны YouTube** | Средняя | Высокое | Использование прокси (поддержка в конфиге), снижение частоты запросов. |
| **Утечки памяти (FFmpeg/Python)** | Низкая | Среднее | Корректное завершение процессов FFmpeg, очистка объектов в `after_playing`. |
| **Изменение Discord API** | Низкая | Высокое | Фиксация версий библиотек в `requirements.txt`. |
